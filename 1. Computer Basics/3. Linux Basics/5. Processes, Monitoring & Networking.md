## Introduction

Understanding **processes**, **monitoring**, and **networking** is essential for full-stack AI developers — especially when deploying models, managing compute servers, debugging networking issues, or optimizing performance on Linux systems.

This tutorial covers:

- how Linux processes work  
- how to monitor system resources  
- how to check logs  
- how networking works on Linux  
- essential tools for AI developers

## Understanding Linux Processes

### What Is a Process?

A **process** is a running program, containing:

- code  
- memory  
- CPU usage  
- open files  
- network connections  

Each process has a **PID** (Process ID).

---

### Foreground vs Background Processes

#### Run in foreground

```bash
python3 train.py
```

#### Run in background

```bash
python3 train.py &
```

#### Suspend a running process

Press:

```text
CTRL + Z
```

#### Resume in background

```bash
bg
```

#### Bring back to foreground

```bash
fg
```

---

### Viewing Processes (ps, top, htop)

#### List all processes

```bash
ps aux
```

#### Real-time system monitor

```bash
top
```

#### Better interactive monitor (recommended)

```bash
sudo apt install htop
htop
```

You can sort by memory, CPU, kill processes, and inspect details visually.

---

### Killing Processes

#### Kill by PID

```bash
kill 1234
```

#### Force-kill

```bash
kill -9 1234
```

#### Kill by process name

```bash
pkill python
```

---

### Job Control (bg, fg, jobs)

#### View jobs

```bash
jobs
```

#### Resume in background

```bash
bg %1
```

#### Resume in foreground

```bash
fg %1
```

---

### Systemd Services

List services:

```bash
systemctl list-units --type=service
```

Start service:

```bash
sudo systemctl start nginx
```

Enable on boot:

```bash
sudo systemctl enable docker
```

Check status:

```bash
systemctl status ssh
```

## System Monitoring

### CPU & Memory Usage

#### Check CPU

```bash
lscpu

```

#### Check memory

```bash

```

---

### Disk Usage & File Systems

#### Disk space

```bash
df -h
```

#### Directory size

```bash
du -sh /path/to/dir
```

#### List block devices

```bash
lsblk
```

---

### Logs & Journalctl

Linux stores logs in `/var/log`.

#### View system logs

```bash
journalctl
```

#### Show logs for a service

```bash
journalctl -u docker
```

#### Follow logs in real time

```bash
journalctl -u ssh -f
```

## Linux Networking Fundamentals

### Network Interfaces (ip, ifconfig)

Check interfaces:

```bash
ip a
```

Bring interface up or down:

```bash
sudo ip link set eth0 up
sudo ip link set eth0 down
```

Older command:

```bash
ifconfig
```

---

### Testing Connectivity (ping, traceroute)

Ping:

```bash
ping google.com
```

Traceroute:

```bash
traceroute google.com
```

---

### DNS Tools (dig, nslookup)

Check DNS resolutions:

```bash
dig openai.com
nslookup openai.com
```

---

### Ports & Services (netstat, ss)

Check open ports:

```bash
sudo ss -tulnp
```

List TCP connections:

```bash
netstat -tulpn
```

---

### Secure Shell (SSH)

SSH is essential for cloud AI development.

#### Connect to a server

```bash
ssh user@host
```

#### Copy files

```bash
scp file.txt user@server:/path/
```

#### Transfer directories

```bash
rsync -av folder/ user@server:/path/
```

---

### Firewall Basics (ufw)

UFW = Uncomplicated Firewall (Ubuntu)

Enable firewall:

```bash
sudo ufw enable
```

Allow SSH:

```bash
sudo ufw allow ssh
```

Check rules:

```bash
sudo ufw status
```

## Practical Skills for AI Developers

As an AI developer, you will often:

- monitor GPU/CPU usage during training  
- SSH into remote GPU servers  
- check logs for crashed experiments  
- monitor disk space when datasets grow  
- manage services (Docker, Jupyter)  
- test connectivity to APIs or servers  

This tutorial gives you the foundation to perform all of these tasks efficiently.

---

## Best Practices

- Use `htop` to monitor long training tasks  
- Keep logs clean; archive old ones  
- Always allow SSH *before* enabling UFW  
- Use `systemctl` instead of older init scripts  
- Monitor disk space to avoid crashes during training  
- Use `rsync` instead of `scp` for large datasets  
- Automate monitoring using cron jobs
