## Introduction

Linux is a powerful, open-source operating system widely used in server environments, cloud infrastructure, and AI/ML development.  
Understanding Linux fundamentals is crucial for full-stack AI developers, as most production systems, cloud services, and containerized workflows rely on Linux.

This tutorial introduces Linux, its distributions, the file system, and guides you through installation and initial setup.

---

## What is Linux?

### History of Linux

- Developed by Linus Torvalds in 1991  
- Open-source and community-driven  
- Evolved into a versatile OS for desktops, servers, embedded systems, and cloud computing  

### Linux Distributions

A **distribution (distro)** is a packaged version of Linux, including the kernel, system utilities, and often software:

- **Ubuntu** — user-friendly, widely used in AI and cloud  
- **Debian** — stable, foundation for many distros  
- **Fedora** — cutting-edge, with latest features  
- **CentOS / Rocky Linux / AlmaLinux** — enterprise-grade, server-focused  
- **Arch Linux** — minimal, highly customizable  
- **Kali Linux** — security-focused  
- **Others** — Mint, Manjaro, OpenSUSE, etc.

> As a full-stack AI developer, **Ubuntu LTS** or **Debian** is recommended for stability and broad library support.

### Kernel vs User Space

- **Kernel** — core of the OS, manages hardware, memory, processes, and drivers  
- **User Space** — environment for applications, shells, and user programs  
- Understanding this separation helps troubleshoot issues, manage permissions, and optimize AI workloads

## Why Linux is Essential for AI Development

- **Production Servers** — most cloud VMs run Linux  
- **Containerization & MLOps** — Docker and Kubernetes rely on Linux kernel features  
- **GPU & AI Frameworks** — NVIDIA drivers, CUDA, cuDNN, PyTorch, TensorFlow  
- **Automation & Scripting** — Bash/Zsh scripting for pipelines, training, and deployment  
- **Open-Source Ecosystem** — ready access to Python, C++, libraries, and tools

## Linux Installation & Setup

### Choosing a Distribution

Consider your goals:

| Goal | Recommended Distro |
|------|------------------|
| AI development / research | Ubuntu LTS, Debian |
| Cutting-edge packages | Fedora, Arch |
| Enterprise / server | CentOS, Rocky Linux, AlmaLinux |
| Security testing | Kali Linux |

---

### Installation Methods

1. **Dual-Boot** — run Linux alongside Windows  
2. **Virtual Machine** — VirtualBox, VMware Workstation  
3. **Cloud VM** — AWS EC2, GCP Compute Engine, Azure VM  
4. **WSL** — Windows Subsystem for Linux (if primarily on Windows)

---

### Initial Setup

After installation:

1. Update system packages:

```bash
sudo apt update && sudo apt upgrade -y   # Debian/Ubuntu
sudo dnf update                          # Fedora
sudo yum update                          # CentOS/RHEL
```

2. Create a non-root user for development:

```bash
sudo adduser devuser
sudo usermod -aG sudo devuser
```

3. Enable SSH for remote access:

```bash
sudo systemctl enable ssh
sudo systemctl start ssh
```

4. Configure firewall (basic):

```bash
sudo ufw enable
sudo ufw allow ssh
sudo ufw status
```

---

### Package Managers and Repositories

Linux package managers simplify software installation:

- **APT (Debian/Ubuntu):** `apt install <package>`  
- **YUM / DNF (CentOS/Fedora):** `yum install <package>` or `dnf install <package>`  
- **Pacman (Arch Linux):** `pacman -S <package>`  

Repositories can be added for additional software (e.g., PPAs in Ubuntu):

```bash
sudo add-apt-repository ppa:deadsnakes/ppa   # Python versions
sudo apt update
```

## Linux File System Overview

### Directory Structure

Common directories:

| Directory | Purpose |
|-----------|---------|
| `/`       | Root directory |
| `/home`  | User home directories |
| `/etc`   | Configuration files |
| `/var`   | Variable data (logs, databases) |
| `/usr`   | Installed software and libraries |
| `/bin`   | Essential binaries |
| `/sbin`  | System binaries |
| `/tmp`   | Temporary files |
| `/dev`   | Device files |
| `/proc`  | Kernel and process info |

---

### Absolute vs Relative Paths

- **Absolute Path** — starts from root (`/`): `/home/devuser/projects`)  
- **Relative Path** — starts from current directory (`./` or `../`): `./myproject`  

---

### Hidden Files and Dotfiles

- Files starting with `.` are hidden (`.bashrc`, `.gitconfig`)  
- Commonly used for configuration  
- List all files including hidden:

```bash
ls -a
```

- Edit configuration dotfiles for environment variables, aliases, and shell settings

---

## Best Practices

- Always keep the system updated  
- Use a non-root user for development  
- Familiarize yourself with directory structure before creating projects  
- Use package managers instead of manual downloads  
- Keep dotfiles organized and version-controlled
