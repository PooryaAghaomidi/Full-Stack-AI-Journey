## Security Fundamentals

Linux is extremely secure by design, but you must configure and manage it properly. This section covers the core security concepts you’ll use daily.

---

### User Accounts

View logged-in users:

```bash
who
w
```

Add user:

```bash
sudo adduser username
```

Delete user:

```bash
sudo deluser username
```

---

### Groups

Check groups:

```bash
groups
```

Add to group:

```bash
sudo usermod -aG groupname username
```

Common groups:

- `sudo` — admin privileges  
- `docker` — run Docker without sudo  

---

### Switching Users

```bash
su - username
```

Switch to root (if enabled):

```bash
sudo su -
```

---

### Password Management

Change current user password:

```bash
passwd
```

Change another user’s password:

```bash
sudo passwd username
```

---

### sudo & Privilege Control

List sudo privileges:

```bash
sudo -l
```

Edit sudo rules:

```bash
sudo visudo
```

Tips:

- Give minimal permissions  
- Avoid enabling root login  
- Never share sudo accounts  

---

### SSH Security

SSH is essential for cloud servers.

### Generate Key Pair

```bash
ssh-keygen -t ed25519
```

Your public key goes on the server:

```bash
~/.ssh/id_ed25519.pub
```

Copy key to server:

```bash
ssh-copy-id user@server
```

---

#### Disable Password Login (optional but strong security)

Edit:

```bash
sudo nano /etc/ssh/sshd_config
```

Set:

```text
PasswordAuthentication no
PermitRootLogin no
```

Restart SSH:

```bash
sudo systemctl restart ssh
```

---

### Firewalls (UFW)

Enable firewall:

```bash
sudo ufw enable
```

Allow SSH:

```bash
sudo ufw allow ssh
```

Allow custom ports:

```bash
sudo ufw allow 8080
```

Check status:

```bash
sudo ufw status
```

---

### Fail2Ban

Protects against repeated login attempts.

Install:

```bash
sudo apt install fail2ban
```

Enable:

```bash
sudo systemctl enable --now fail2ban
```

View logs:

```bash
sudo fail2ban-client status
```

---

### File & Directory Security

View permissions:

```bash
ls -l
```

Change permissions:

```bash
chmod 600 file
chmod 755 script.sh
```

Change owner:

```bash
sudo chown user:group filename
```

---

### System Hardening Basics

- Disable unused services  
- Keep software updated (`apt update && apt upgrade`)  
- Use SSH keys instead of passwords  
- Restrict sudo  
- Monitor logs (`journalctl`, `/var/log/auth.log`)

## Useful Linux Utilities

Linux includes hundreds of powerful tools. These are essential.

---

### Text Processing Tools

#### grep – search text

```bash
grep "keyword" file.txt
```

#### sed – text editing

```bash
sed 's/old/new/g' file.txt
```

#### awk – structured text processing

```bash
awk '{print $1}' data.txt
```

#### cut – extract columns

```bash
cut -d"," -f2 file.csv
```

---

### Search Tools

#### find

```bash
find /path -name "*.txt"
```

#### locate

```bash
locate filename
```

(Requires `sudo updatedb` sometimes)

---

### Compression Tools

ZIP:

```bash
zip archive.zip file1 file2
unzip archive.zip
```

TAR:

```bash
tar -czvf archive.tar.gz folder/
tar -xzvf archive.tar.gz
```

---

### System Info Tools

#### CPU

```bash
lscpu
```

#### Memory

```bash
free -h
```

#### PCI devices (GPU info)

```bash
lspci | grep -i nvidia
```

#### USB devices

```bash
lsusb
```

---

### Disk & Storage Tools

Disk usage:

```bash
df -h
```

Directory size:

```bash
du -sh folder/
```

Mount disks:

```bash
mount /dev/sda1 /mnt
```

---

### Networking Utilities

Ping:

```bash
ping google.com
```

Check open ports:

```bash
sudo lsof -i -P -n
```

DNS lookup:

```bash
dig example.com
```

IP info:

```bash
ip a
```

## Cloud Development Essentials

Cloud servers (AWS, Azure, GCP, Oracle, Linode, DigitalOcean, etc.) all rely heavily on Linux.

---

### Cloud CLI Tools

#### AWS

```bash
sudo apt install awscli
aws configure
```

#### GCP

```bash
sudo snap install google-cloud-cli --classic
```

#### Azure

```bash
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash
```

These tools let you manage VMs, storage, networking, and deployments directly from Linux.

---

### SSH Keys for Cloud Servers

Cloud workflow:

1. Create SSH key  
2. Add public key to cloud VM  
3. Login securely  

Example:

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@your-server-ip
```

---

### Server Provisioning

Once connected:

```bash
sudo apt update && sudo apt upgrade
sudo apt install git python3 pip
sudo apt install docker.io
```

---

### Managing Remote Linux Machines

#### Upload files

```bash
scp file.txt user@server:/home/user/
```

#### Download files

```bash
scp user@server:/path/file.txt .
```

#### Remote command

```bash
ssh user@server "ls -lah /var"
```

---

### Basic Automation & Deployment

Use bash scripts to:

- install dependencies  
- configure firewalls  
- set environment variables  
- deploy applications  

Example deploy script:

```bash
#!/bin/bash
git pull
docker-compose down
docker-compose up -d
```

---

### SSH Tunneling

Local machine → access remote service:

```bash
ssh -L 8888:localhost:8888 user@server
```

Now remote Jupyter is available locally.

---

### Firewall & Security Groups

Cloud firewalls:

- allow specific ports  
- restrict external access  
- isolate private networks  

Examples:

- Port 22 → SSH  
- Port 80/443 → Web servers  
- Ports 6006 & 8888 → ML dashboards  

---

### Storage & Backups

#### Sync local to cloud

```bash
rsync -avz folder/ user@server:/backup/
```

#### Object storage (S3 example)

```bash
aws s3 cp file s3://bucket/
```

---

## Best Practices

### Security

- Use SSH keys, disable passwords  
- Enable firewalls and Fail2Ban  
- Update systems weekly  
- Restrict sudo access  
- Never expose unnecessary ports  

### Utilities

- Master `grep`, `find`, `sed`, `awk`  
- Use `df`, `du`, `lsof`, `top`, `journalctl` regularly  
- Compress logs and datasets  

### Cloud Development

- Use SSH automation  
- Use cloud CLI tools  
- Use firewalls + cloud security groups  
- Script your deployments  
- Use backups and snapshots
