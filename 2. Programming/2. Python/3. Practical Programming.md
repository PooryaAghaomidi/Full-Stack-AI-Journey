## Error Handling

Python uses **exceptions** to signal errors. You handle them with `try`, `except`, `else`, and `finally`.

Basic error handling:

```python
try:
    x = int("not a number")
except ValueError:
    print("Invalid number")
```

Catching multiple exception types:

```python
try:
    with open("file.txt") as f:
        data = f.read()
except (FileNotFoundError, PermissionError) as e:
    print("File problem:", e)
```

Using `else` and `finally`:

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("Division error")
else:
    print("Success:", result)
finally:
    print("Runs no matter what")
```

Raising your own errors:

```python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    print("Age set to", age)

set_age(-3)   # error
```

Define custom exceptions:

```python
class LoginError(Exception):
    pass

def login(user):
    if user != "admin":
        raise LoginError("Unauthorized")

login("guest")
```

## File I/O

Use the built-in `open()` function to read/write files.

### Reading files

```python
with open("notes.txt", "r") as f:
    text = f.read()
    print(text)
```

Reading line by line:

```python
with open("data.txt") as f:
    for line in f:
        print(line.strip())
```

### Writing files

```python
with open("output.txt", "w") as f:
    f.write("Hello world\n")
```

Append mode:

```python
with open("log.txt", "a") as f:
    f.write("New entry\n")
```

Reading and writing JSON:

```python
import json

person = {"name": "Alice", "age": 30}

# Write
with open("person.json", "w") as f:
    json.dump(person, f)

# Read
with open("person.json") as f:
    data = json.load(f)
    print(data)
```

## Build Tools / Runtime Model

### How Python executes code

1. You run a `.py` file.
2. Python compiles it to **bytecode** (`.pyc` files).  
3. The **CPython interpreter** executes the bytecode.

This is why Python is often described as interpreted but includes compilation steps.

### Running scripts

```python
python main.py
```

### Packaging Python projects

A minimal `pyproject.toml`:

```python
[project]
name = "myproject"
version = "1.0.0"
dependencies = ["requests"]
```

Build a distribution (requires `build`):

```python
pip install build
python -m build
```

This generates `.whl` and `.tar.gz` files for publishing.

### The Python Runtime

The runtime includes:

- memory management
- garbage collection
- IO libraries
- import system
- standard library

Understanding this helps with performance and debugging.

## Concurrency / Async

Python provides multiple ways to run tasks concurrently, allowing you to speed up programs that wait on I/O or perform heavy computations.  
Below are the three main approaches: **threading**, **multiprocessing**, and **asyncio**, each suited for different types of workloads.

### 1. **Threading** (good for I/O-bound tasks)

Threading means running multiple “lightweight workers” inside the same program at the same time. It works best for I/O-bound tasks, which are tasks that spend most of their time waiting — for example waiting for a file to load, waiting for a web server to reply, or waiting for user input. Since threads can pause while waiting, Python can switch to another thread and keep your program busy instead of sitting idle. Threads share the same memory, so communication is easy, but they must coordinate to avoid accidentally interfering with each other.

Example: Why threading? Downloading files is slow because you wait for the network. Threads let you wait for multiple downloads at the same time.

```python
import threading
import requests

def download(url):
    # This request waits for the server → I/O-bound
    r = requests.get(url)
    print(f"Downloaded {url} → {len(r.content)} bytes")

urls = [
    "https://example.com",
    "https://httpbin.org/get",
    "https://python.org"
]

threads = []
for url in urls:
    t = threading.Thread(target=download, args=(url,))
    threads.append(t)
    t.start()     # Start each download in its own thread

for t in threads:
    t.join()      # Wait for all downloads to finish
```

### 2. **Multiprocessing** (good for CPU-bound tasks)

Multiprocessing creates completely separate processes, each running its own Python interpreter. This is ideal for CPU-bound tasks, which are tasks that spend most of their time using the processor, such as heavy calculations, data analysis, or image processing. Because every process has its own memory, they don’t block each other, and they bypass Python’s GIL (Global Interpreter Lock) — a rule that only allows one thread to run Python code at a time. The downside is that processes use more memory and are slower to start, but they are the best choice when raw computing power matters.

Example: Why multiprocessing? Resizing images is CPU-intensive. Processes let Python use multiple CPU cores.

```python
from multiprocessing import Process
from PIL import Image

def resize_image(path):
    img = Image.open(path)
    img = img.resize((300, 300))     # CPU-heavy operation
    img.save(f"resized_{path}")
    print(f"Processed {path}")

files = ["img1.jpg", "img2.jpg", "img3.jpg"]

processes = []
for f in files:
    p = Process(target=resize_image, args=(f,))
    processes.append(p)
    p.start()       # Each process uses a different CPU core

for p in processes:
    p.join()        # Wait until all images are processed
```

### 3. **Asyncio** (async/await)

Asyncio uses an event loop, which is a system that runs many tasks by switching between them whenever they need to wait. Instead of creating threads or processes, tasks voluntarily pause themselves with await, giving control back to the event loop. This makes asyncio extremely efficient for handling thousands of network operations at once with very little overhead. It’s great for web servers or any situation where you are mostly doing I/O but want high performance. It’s single-threaded, so there’s no thread interference, but it requires writing your code using async and await.

Example: Why asyncio? When you need to hit many APIs quickly, asyncio handles thousands of requests without threads.

```python
import asyncio
import aiohttp

async def fetch_price(session, product_id):
    # Non-blocking HTTP request
    url = f"https://fakestoreapi.com/products/{product_id}"
    async with session.get(url) as resp:
        data = await resp.json()
        print(f"{product_id}: {data['title']}")

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [
            fetch_price(session, pid)
            for pid in range(1, 6)    # Fetch 5 products in parallel
        ]
        await asyncio.gather(*tasks)  # Run all requests concurrently

asyncio.run(main())
```

| Feature / Model  | Threading (I/O-bound)          | Multiprocessing (CPU-bound)          | Asyncio (High-performance I/O)   |
| ---------------- | ------------------------------ | ------------------------------------ | -------------------------------- |
| Best for         | I/O-bound tasks                | CPU-bound tasks                      | Many concurrent I/O ops          |
| Executes in      | Same process, multiple threads | Multiple processes (separate memory) | Single-threaded event loop       |
| Overcomes GIL?   | ❌ No                          | ✅ Yes                              | N/A (cooperative multitasking)   |
| Memory usage     | Low                            | High                                 | Very low                         |
| Difficulty level | Easy                           | Medium                               | Medium (requires async/await)    |
| When to use      | Network calls, file waits      | Heavy math, data processing          | Many web requests, async servers |

## Common Gotchas / Tips

### 1. Indentation errors

Python uses indentation for blocks — be consistent with spaces.

```python
if True:
print("oops")   # error
```

### 2. Mutable default arguments

```python
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))  # [1]
print(add_item(2))  # [1, 2]  <-- unexpected!
```

Fix:

```python
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

### 3. Integer division difference

```python
5 / 2   # 2.5
5 // 2  # 2
```

### 4. Copying lists incorrectly

```python
a = [1,2,3]
b = a
b.append(4)
print(a)   # [1,2,3,4]
```

Fix:

```python
b = a.copy()
```

### 5. Import shadowing

Don’t name your file `json.py` or `random.py` — it breaks imports.

### 6. `__main__` pattern for scripts

```python
if __name__ == "__main__":
    main()
```

### 7. Use virtual environments for every project

Avoid dependency conflicts.
