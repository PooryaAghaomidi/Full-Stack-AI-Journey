## Transactions Across Multiple Tables

When multiple tables need **consistent updates**, use transactions to ensure **atomicity**.

### Example: Bank Transfer

```sql
BEGIN;

-- Deduct from sender
UPDATE accounts SET balance = balance - 100 WHERE id = 1;

-- Add to recipient
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;
```

- If any statement fails, **ROLLBACK** ensures no partial changes occur:

```sql
ROLLBACK;
```

**Tip:** Always wrap related operations in a transaction to maintain **data integrity**.

## Handling NULL Values

`NULL` represents **missing or unknown data**. Handling NULLs is crucial for accurate queries.

### Checking for NULL

```sql
SELECT * FROM employees WHERE phone IS NULL;
```

### Using COALESCE

- Returns the **first non-NULL value**

```sql
SELECT name, COALESCE(phone, 'N/A') AS phone_number FROM employees;
```

### Aggregate Functions and NULL

- `COUNT(column)` ignores NULLs  
- `SUM`, `AVG` skip NULL values by default  

### Comparison Pitfalls

- `NULL = NULL` → returns FALSE  
- Use `IS NULL` or `IS NOT NULL` instead

## Recursive Queries

Recursive queries allow you to **query hierarchical or nested data**.

### Example: Employee Hierarchy (PostgreSQL)

```sql
WITH RECURSIVE EmployeeHierarchy AS (
    SELECT id, name, manager_id
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, e.manager_id
    FROM employees e
    INNER JOIN EmployeeHierarchy eh ON e.manager_id = eh.id
)
SELECT * FROM EmployeeHierarchy;
```

- `WITH RECURSIVE` repeatedly applies the query until all levels are processed

## Full-Text Search

Full-text search enables **efficient searching in large text fields**.

### MySQL Example

```sql
CREATE FULLTEXT INDEX idx_description ON projects(description);

SELECT * FROM projects
WHERE MATCH(description) AGAINST('AI development' IN NATURAL LANGUAGE MODE);
```

### PostgreSQL Example

```sql
SELECT *
FROM projects
WHERE to_tsvector(description) @@ to_tsquery('AI & development');
```

- Supports ranking, stemming, and advanced text search

## JSON Support in Modern Databases

Modern SQL databases support **semi-structured JSON data**.

### PostgreSQL Example

```sql
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    data JSONB
);

INSERT INTO employees (name, data) VALUES 
('Alice', '{"skills": ["Python", "SQL"], "experience": 3}');
```

### Querying JSON Data

```sql
SELECT name, data->'skills' AS skills
FROM employees
WHERE data->>'experience' = '3';
```

- JSON functions allow **extracting, filtering, and aggregating nested data**

## ETL / Data Pipelines Basics

ETL (Extract, Transform, Load) is critical for **moving and preparing data** for AI and analytics.

### Example Workflow

1. **Extract**: Pull data from multiple sources (databases, CSV, APIs)  
2. **Transform**: Clean, aggregate, or enrich data with SQL  
3. **Load**: Insert transformed data into a data warehouse or analytics DB

### SQL in ETL

- Filtering and aggregating:

```sql
INSERT INTO analytics.sales_summary (region, total_sales)
SELECT region, SUM(amount)
FROM sales
WHERE sale_date >= '2025-01-01'
GROUP BY region;
```

- Can be **scheduled with cron, Airflow, or other pipeline tools**  

**Tip:** Efficient queries and indexing improve ETL performance for large datasets.
