## Introduction

Indexes are **database objects that improve query performance** by allowing faster data retrieval. Proper use of indexes can drastically reduce query execution time in large databases.

This tutorial covers:

- Types of indexes  
- When and how to use them  
- Query optimization techniques  
- How to analyze queries using `EXPLAIN` or `EXPLAIN ANALYZE`  

---

## Index Types

### Single-Column Index

- Index on **one column**  
- Speeds up queries filtering or sorting by this column

```sql
CREATE INDEX idx_employee_name ON employees(name);
```

### Composite Index

- Index on **multiple columns**  
- Useful for queries filtering by multiple columns

```sql
CREATE INDEX idx_dept_salary ON employees(department_id, salary);
```

### Unique Index

- Ensures column values are **unique**  
- Also improves performance for lookup queries

```sql
CREATE UNIQUE INDEX idx_unique_email ON employees(email);
```

### Full-Text Index

- Used for **searching text content**  
- Supports operations like `MATCH ... AGAINST` (MySQL) or `to_tsvector()` (PostgreSQL)

```sql
-- MySQL example
CREATE FULLTEXT INDEX idx_fulltext_description ON projects(description);
```

---

## When and How to Use Indexes

- Index **columns used frequently** in `WHERE`, `JOIN`, `ORDER BY` clauses  
- Avoid indexing **columns with low cardinality** (few unique values)  
- Consider **composite indexes** when multiple columns are commonly queried together  
- Remember: indexes **consume disk space** and **slow down INSERT/UPDATE/DELETE**  

**Example Use Case**

```sql
-- Frequently querying employees by department and salary
SELECT * FROM employees
WHERE department_id = 2 AND salary > 50000
ORDER BY salary DESC;
-- Use composite index: idx_dept_salary
```

---

## Query Optimization Tips

- **Select only needed columns**: avoid `SELECT *`  
- **Use proper indexes** on filtering/join columns  
- **Avoid functions on indexed columns** in WHERE clauses  
- **Use JOINs efficiently**; prefer indexed columns for joins  
- **Analyze query plans** before optimizing complex queries  

**Example: Inefficient vs Efficient**

Inefficient:

```sql
SELECT * FROM employees WHERE UPPER(name) = 'ALICE';
```

Efficient:

```sql
-- Index on name column without function
SELECT * FROM employees WHERE name = 'Alice';
```

## Understanding EXPLAIN / EXPLAIN ANALYZE

### EXPLAIN

- Provides **query execution plan**  
- Shows how the database scans tables, uses indexes, joins, and filters

```sql
EXPLAIN SELECT * FROM employees WHERE department_id = 2;
```

- Output typically includes:  
  - `type`: scan type (ALL, INDEX, RANGE)  
  - `possible_keys`: which indexes can be used  
  - `rows`: estimated rows scanned  
  - `Extra`: notes like "Using where", "Using index"

### EXPLAIN ANALYZE (PostgreSQL)

- Executes the query and **provides actual runtime statistics**  
- Helps identify bottlenecks

```sql
EXPLAIN ANALYZE SELECT * FROM employees WHERE salary > 50000;
```
