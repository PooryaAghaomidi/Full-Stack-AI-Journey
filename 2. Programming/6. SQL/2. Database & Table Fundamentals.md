## Databases, Schemas, and Tables

### Databases

A **database** is a container that stores organized data. It can contain multiple tables, views, indexes, and other objects.

- **Example:** A company database might include tables for employees, departments, and projects.

### Schemas

A **schema** is a logical collection of database objects (tables, views, functions). Schemas help organize and manage permissions.

- In PostgreSQL, default schema is `public`.
- In SQL Server, default schema is `dbo`.

### Tables

Tables store **structured data in rows and columns**:

- Columns: define the type of data stored (name, age, salary)  
- Rows: individual records  
- Every table should have a **primary key** (unique identifier)

**Example Table: `employees`**

| id | name     | department | age | salary  |
|----|----------|------------|-----|---------|
| 1  | Alice    | HR         | 25  | 50000   |
| 2  | Bob      | IT         | 30  | 60000   |
| 3  | Charlie  | Finance    | 28  | 55000   |

## Data Types

Choosing the correct **data type** ensures proper storage and operations.

### Numeric Types

- `INT` / `INTEGER`: whole numbers  
- `SMALLINT`: smaller range integers  
- `BIGINT`: large integers  
- `DECIMAL` / `NUMERIC`: exact precision decimal numbers (money)  
- `FLOAT` / `REAL`: approximate decimal numbers

### Text Types

- `CHAR(n)`: fixed-length string  
- `VARCHAR(n)`: variable-length string  
- `TEXT`: large variable-length text

### Date & Time Types

- `DATE`: YYYY-MM-DD  
- `TIME`: HH:MM:SS  
- `DATETIME` / `TIMESTAMP`: combined date and time  
- `INTERVAL`: duration (PostgreSQL)

### Boolean

- `BOOLEAN` or `BOOL` → `TRUE` / `FALSE`

**Example Table with Data Types**

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department VARCHAR(50),
    age INT,
    salary DECIMAL(10,2),
    hire_date DATE,
    is_active BOOLEAN
);
```

## Primary Keys, Foreign Keys, Unique Constraints

### Primary Key (PK)

- Uniquely identifies each row in a table  
- Cannot be NULL  
- Only one PK per table

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

### Foreign Key (FK)

- Establishes a **relationship between two tables**  
- Must match a primary key in the referenced table

```sql
CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);
```

### Unique Constraint

- Ensures **all values in a column are distinct**  
- A table can have multiple unique constraints

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE
);
```

## Creating, Modifying, and Dropping Tables

### Create Table

```sql
CREATE TABLE projects (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    start_date DATE,
    end_date DATE
);
```

### Modify Table

- **Add Column**

```sql
ALTER TABLE employees ADD COLUMN phone VARCHAR(15);
```

- **Modify Column Type**

```sql
ALTER TABLE employees ALTER COLUMN salary DECIMAL(12,2);
```

- **Drop Column**

```sql
ALTER TABLE employees DROP COLUMN phone;
```

### Drop Table

```sql
DROP TABLE IF EXISTS employees;
```

**Tip:** Always use `IF EXISTS` to avoid errors when dropping tables.

## Understanding Indexes

### What is an Index?

An **index** is a database object that improves query performance by allowing faster data retrieval.

- Think of it as a **table of contents** for the table.
- Does **not change data**; only improves lookup speed.
- Comes with **storage and update cost**.

### Creating Index

```sql
CREATE INDEX idx_employee_name ON employees(name);
```

### Unique Index

- Guarantees column values are unique:

```sql
CREATE UNIQUE INDEX idx_unique_email ON employees(email);
```

### Clustered vs Non-Clustered Index

- **Clustered:** physically sorts data in the table by the indexed column (one per table)  
- **Non-Clustered:** creates a separate structure pointing to table rows (multiple allowed)

### Using Indexes in Queries

```sql
SELECT * FROM employees WHERE name = 'Alice';
-- Index idx_employee_name speeds up this query
```

**Tip:** Index columns used frequently in `WHERE`, `JOIN`, `ORDER BY` for better performance. Avoid indexing every column as it slows down writes.
