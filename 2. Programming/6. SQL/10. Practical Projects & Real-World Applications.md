## Introduction

SQL is a **core tool for data preparation** in AI workflows. Real-world applications often involve:

- Designing structured databases for storing raw data

- Feeding clean and structured datasets into machine learning models  

This tutorial walks through **practical examples** showing how SQL integrates into AI projects.

## Designing a Relational Database Schema for an AI Project

### Example: E-commerce Recommendation System

Tables:

1. `users` - stores user information  
2. `products` - stores product information  
3. `orders` - tracks purchases  
4. `ratings` - user ratings for products  

### Example Schema

```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100) UNIQUE,
    signup_date DATE
);

CREATE TABLE products (
    product_id INT PRIMARY KEY,
    name VARCHAR(100),
    category VARCHAR(50),
    price DECIMAL(10,2)
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    user_id INT,
    product_id INT,
    quantity INT,
    order_date DATE,
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    FOREIGN KEY (product_id) REFERENCES products(product_id)
);

CREATE TABLE ratings (
    rating_id INT PRIMARY KEY,
    user_id INT,
    product_id INT,
    rating INT CHECK (rating BETWEEN 1 AND 5),
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    FOREIGN KEY (product_id) REFERENCES products(product_id)
);
```

- Use **primary keys** for uniqueness  
- Use **foreign keys** to maintain relationships  
- Use **check constraints** to validate data

## Writing Queries to Extract Features for Machine Learning

### Example: User-Product Interaction Features

- Count of purchases per user:

```sql
SELECT user_id, COUNT(order_id) AS total_orders
FROM orders
GROUP BY user_id;
```

- Average rating per product:

```sql
SELECT product_id, AVG(rating) AS avg_rating
FROM ratings
GROUP BY product_id;
```

- Combine features with JOIN:

```sql
SELECT u.user_id, u.name, COUNT(o.order_id) AS total_orders, AVG(r.rating) AS avg_rating
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
LEFT JOIN ratings r ON u.user_id = r.user_id
GROUP BY u.user_id, u.name;
```

## Aggregating and Transforming Data

- Normalize numeric features:

```sql
SELECT user_id,
       (COUNT(order_id) - MIN(COUNT(order_id)) OVER())::DECIMAL /
       (MAX(COUNT(order_id)) OVER() - MIN(COUNT(order_id)) OVER()) AS normalized_orders
FROM orders
GROUP BY user_id;
```

- Pivot categorical data:

```sql
SELECT user_id,
       SUM(CASE WHEN category = 'Electronics' THEN quantity ELSE 0 END) AS electronics_count,
       SUM(CASE WHEN category = 'Clothing' THEN quantity ELSE 0 END) AS clothing_count
FROM orders o
JOIN products p ON o.product_id = p.product_id
GROUP BY user_id;
```

- Extract time-based features:

```sql
SELECT user_id,
       EXTRACT(MONTH FROM order_date) AS order_month,
       COUNT(order_id) AS monthly_orders
FROM orders
GROUP BY user_id, EXTRACT(MONTH FROM order_date);
```

## Connecting SQL with Python/Pandas for AI Workflows

### Using `pandas` to Load SQL Data

```python
import pandas as pd
import sqlite3  # or use psycopg2 for PostgreSQL

# Connect to database
conn = sqlite3.connect('ecommerce.db')

# Query data
query = """
SELECT u.user_id, u.name, COUNT(o.order_id) AS total_orders, AVG(r.rating) AS avg_rating
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
LEFT JOIN ratings r ON u.user_id = r.user_id
GROUP BY u.user_id, u.name;
"""

df = pd.read_sql_query(query, conn)
print(df.head())

conn.close()
```

### Feature Engineering in Pandas

- Scale or normalize features
- Encode categorical variables
- Merge multiple SQL tables into a **single dataset** for ML models

**Tip:** SQL handles aggregation efficiently; Pandas complements with **cleaning, transformation, and modeling**.
