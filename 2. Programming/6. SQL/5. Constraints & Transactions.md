## Introduction

Constraints and transactions are essential for **data integrity, consistency, and reliability** in relational databases. This tutorial covers:

- Defining rules for table data (constraints)  
- Automatically generating unique IDs (auto-increment/sequences)  
- Performing multiple SQL operations safely using transactions  
- Managing concurrency with isolation levels and locks  
- Handling errors to ensure consistent data  

Mastering these topics allows developers to **build reliable, production-ready databases**.

## Primary Key, Foreign Key, Unique, Not Null, Check

### Primary Key (PK)

- Uniquely identifies each row  
- Cannot contain NULL values  

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);
```

### Foreign Key (FK)

- Establishes relationship between tables  
- Ensures referential integrity  

```sql
CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);
```

### Unique Constraint

- Ensures column values are unique  

```sql
CREATE TABLE employees (
    email VARCHAR(100) UNIQUE
);
```

### Not Null

- Ensures a column cannot have NULL values  

```sql
CREATE TABLE employees (
    name VARCHAR(50) NOT NULL
);
```

### Check Constraint

- Ensures values meet a condition  

```sql
CREATE TABLE employees (
    age INT CHECK (age >= 18)
);
```

## Auto-Increment / Sequences

### Auto-Increment (MySQL, SQLite)

- Automatically generates unique IDs  

```sql
CREATE TABLE employees (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50)
);
```

### Sequences (PostgreSQL)

```sql
CREATE SEQUENCE employee_seq START 1 INCREMENT 1;
CREATE TABLE employees (
    id INT PRIMARY KEY DEFAULT nextval('employee_seq'),
    name VARCHAR(50)
);
```

**Tip:** Auto-increment ensures **unique primary keys** without manual input.

## Transactions, Commits, Rollbacks

### What is a Transaction?

- A **transaction** is a group of SQL operations executed as a single unit.  
- Follows **ACID properties** (Atomicity, Consistency, Isolation, Durability).

### Example

```sql
BEGIN;

INSERT INTO accounts (id, balance) VALUES (1, 1000);
INSERT INTO accounts (id, balance) VALUES (2, 2000);

COMMIT;
```

### Rollback

- Reverts changes if an error occurs  

```sql
BEGIN;

INSERT INTO accounts (id, balance) VALUES (1, 1000);
INSERT INTO accounts (id, balance) VALUES (2, 2000);

ROLLBACK;  -- No changes saved
```

**Tip:** Always use transactions when performing multiple related operations.

## Isolation Levels and Locks

### Isolation Levels

Control how concurrent transactions interact.

| Level | Description |
|-------|-------------|
| READ UNCOMMITTED | Can read uncommitted changes (dirty read) |
| READ COMMITTED   | Can only read committed changes |
| REPEATABLE READ  | Prevents non-repeatable reads |
| SERIALIZABLE     | Full isolation, highest consistency, lowest concurrency |

**Example (PostgreSQL):**

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

### Locks

- **Row-level locks**: prevent other transactions from modifying a row  
- **Table-level locks**: prevent changes to the entire table  
- Proper locking avoids **race conditions** and **data corruption**

## Handling Errors in Transactions

### Using Try-Catch in SQL (PostgreSQL / PL/pgSQL)

```sql
DO $$
BEGIN
    BEGIN TRANSACTION;
    INSERT INTO accounts(id, balance) VALUES (1, 1000);
    INSERT INTO accounts(id, balance) VALUES (1, 500); -- duplicate PK
    COMMIT;
EXCEPTION
    WHEN unique_violation THEN
        ROLLBACK;
        RAISE NOTICE 'Transaction failed and rolled back';
END $$;
```

### Best Practices

- Always **wrap multiple operations in a transaction**  
- **Validate data** before inserting/updating  
- Handle errors programmatically in application code
