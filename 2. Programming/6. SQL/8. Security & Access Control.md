## Introduction

Database security ensures that **only authorized users** can access or modify data, while protecting against malicious attacks like **SQL injection**. In this tutorial, you will learn:

- How to manage users and roles  
- Granting and revoking permissions  
- Preventing SQL injection  
- Best practices for secure database design  

Mastering these topics ensures **safe, reliable, and production-ready databases**.

---

## Users and Roles

### Users

- Represent **individual accounts** that can log into the database  
- Each user has a **username and authentication method**  

```sql
-- MySQL
CREATE USER 'alice'@'localhost' IDENTIFIED BY 'strongpassword';
```

### Roles

- Roles are **collections of privileges** that can be assigned to multiple users  
- Simplifies **permission management**  

```sql
-- PostgreSQL
CREATE ROLE analyst;
GRANT SELECT ON employees TO analyst;

-- Assign role to user
GRANT analyst TO alice;
```

---

## Privileges and Permissions

### Privileges

- Define **what a user/role can do**  
- Examples: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `DROP`

### Granting Privileges

```sql
-- MySQL example
GRANT SELECT, INSERT ON employees TO 'alice'@'localhost';
```

### Revoking Privileges

```sql
REVOKE INSERT ON employees FROM 'alice'@'localhost';
```

### Best Practices

- **Least Privilege Principle:** give users only the permissions they need  
- Use roles for **group management** rather than individual privileges

## SQL Injection: Prevention Techniques

### What is SQL Injection?

- An attack where **malicious SQL code is inserted** into queries  
- Can lead to **data theft, modification, or deletion**

### Example of Vulnerable Query (Python)

```python
user_input = "1 OR 1=1"
query = "SELECT * FROM employees WHERE id = " + user_input
cursor.execute(query)
```

- This query returns **all employees**, bypassing intended filtering

### Prevention Techniques

1. **Parameterized Queries / Prepared Statements**

```python
query = "SELECT * FROM employees WHERE id = %s"
cursor.execute(query, (user_input,))
```

2. **Stored Procedures**

- Encapsulate logic in the database; reduces direct user input exposure

3. **Input Validation**

- Ensure input is of **expected type, length, and format**  

4. **Escaping User Input**

- Only when parameterized queries are not available (less preferred)

## Best Practices for Secure Database Access

1. **Strong Passwords**  
   - Enforce complex passwords and rotate periodically

2. **Limit Network Access**  
   - Restrict database access to trusted hosts or networks

3. **Use Roles Instead of Individual Privileges**  
   - Simplifies management and reduces errors

4. **Audit and Monitor Database Activity**  
   - Log access and queries for anomaly detection

5. **Encrypt Sensitive Data**  
   - At rest (disk encryption) and in transit (SSL/TLS)

6. **Regular Updates and Patches**  
   - Keep database software up-to-date to fix security vulnerabilities
