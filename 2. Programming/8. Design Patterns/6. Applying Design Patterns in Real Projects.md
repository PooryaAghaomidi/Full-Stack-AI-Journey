## Introduction

Design patterns are **most powerful when applied in real-world projects**.  
They help **refactor existing code**, build **robust systems**, and improve **team collaboration**.

**Key Points:**

- Patterns improve **readability, maintainability, and scalability**  
- Can be combined to **solve complex problems**  
- Must be **applied thoughtfully** to avoid over-engineering  

---

## Refactoring Legacy Code Using Patterns

Legacy code often lacks structure, leading to **spaghetti code** or tightly coupled components.

**Steps to Refactor:**

1. **Identify repetitive code or poor structures**  
2. Choose an appropriate pattern:
   - Singleton: Replace multiple global instances  
   - Factory: Simplify object creation  
   - Strategy: Replace conditional logic  
3. **Gradually refactor** to avoid breaking functionality

**Python Example: Refactoring Conditional Logic to Strategy**

```python
# Before: Conditional
def calculate(discount_type, amount):
    if discount_type == "student":
        return amount * 0.9
    elif discount_type == "vip":
        return amount * 0.8

# After: Strategy Pattern
class DiscountStrategy:
    def apply(self, amount):
        pass

class StudentDiscount(DiscountStrategy):
    def apply(self, amount):
        return amount * 0.9

class VIPDiscount(DiscountStrategy):
    def apply(self, amount):
        return amount * 0.8

# Usage
strategy = StudentDiscount()
print(strategy.apply(100))  # 90.0
```

## Combining Multiple Patterns

Complex projects often require **multiple patterns working together**.

**Example:** AI model pipeline  

- **Builder:** Construct the model step by step  
- **Factory:** Create different preprocessing components  
- **Observer:** Notify monitoring system after training  

**Python Example (Simplified):**

```python
# Factory for preprocessing
class PreprocessorFactory:
    def create(self, type):
        if type == "normalize": return Normalize()
        if type == "standardize": return Standardize()

# Builder for model
class ModelBuilder:
    def __init__(self):
        self.layers = []
    def add_layer(self, layer): self.layers.append(layer); return self
    def build(self): return self.layers

# Observer for monitoring
class Monitor:
    def update(self, model_info): print("Model trained:", model_info)
```

## Choosing Patterns Based on Requirements

1. **Understand the problem domain**  
2. **Identify pain points** (repetitive code, tight coupling, scalability issues)  
3. **Match with pattern category**:
   - Creation → Creational  
   - Structure → Structural  
   - Communication → Behavioral  
   - Architecture → MVC, Microservices, Layered  
4. **Avoid unnecessary patterns** (Golden Hammer anti-pattern)  

---

## Performance Considerations

- Some patterns introduce **extra layers of abstraction**:
  - Decorator, Proxy, Observer may add runtime overhead  
- Balance **readability vs. performance**  
- Optimize **frequently called paths** and **memory-intensive patterns** like Flyweight for efficiency  
- Profile code when combining patterns in AI pipelines or high-throughput systems

## Design Patterns in Open-Source Projects

Studying open-source code demonstrates **real-world application** of patterns:

1. **Django (Python)**  
   - MVC pattern for web apps  
   - Observer-like signals for event handling  

2. **TensorFlow / PyTorch**  
   - Builder pattern for constructing models  
   - Factory pattern for data preprocessing  

3. **React (JavaScript)**  
   - Observer pattern with state updates  
   - Composition for UI components  

4. **Linux / System Libraries**  
   - Singleton pattern for configuration  
   - Proxy pattern for resource management  

**Tip:** Reading source code helps understand **trade-offs and practical usage** of patterns.
