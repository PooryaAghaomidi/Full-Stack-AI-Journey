## Overview: Object Creation Strategies

**Creational patterns** provide flexible and reusable ways to **instantiate objects**.  
They abstract the **object creation process**, allowing you to **change the type of objects dynamically**, reduce tight coupling, and improve maintainability.

**Key Points:**

- Decouple object creation from usage  
- Support **singleton, prototype, factory, builder patterns**  
- Useful in **AI systems** for creating models, datasets, or components dynamically

---

## Singleton

**Purpose:** Ensure a class has only **one instance** and provide a **global point of access**.

**Use Cases:**

- Logger service  
- Configuration manager  
- Database connection pool

**Python Example:**

```python
class Singleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super(Singleton, cls).__new__(cls)
        return cls._instance

# Usage
s1 = Singleton()
s2 = Singleton()
print(s1 is s2)  # True
```

## Factory Method

**Purpose:** Define an interface for creating an object but let subclasses **decide which class to instantiate**.

**Use Cases:**

- GUI frameworks creating different button types  
- AI pipeline creating different data preprocessors dynamically

**Python Example:**

```python
class Shape:
    def draw(self):
        pass

class Circle(Shape):
    def draw(self):
        print("Drawing Circle")

class Square(Shape):
    def draw(self):
        print("Drawing Square")

class ShapeFactory:
    def create_shape(self, shape_type):
        if shape_type == "circle":
            return Circle()
        elif shape_type == "square":
            return Square()

# Usage
factory = ShapeFactory()
shape = factory.create_shape("circle")
shape.draw()  # Drawing Circle
```

## Abstract Factory

**Purpose:** Provide an **interface for creating families of related objects** without specifying concrete classes.

**Use Cases:**

- UI toolkits for multiple OS  
- Creating components for AI pipelines (e.g., different data loaders, models)

**Python Example:**

```python
class GUIFactory:
    def create_button(self):
        pass

class WindowsFactory(GUIFactory):
    def create_button(self):
        return WindowsButton()

class MacFactory(GUIFactory):
    def create_button(self):
        return MacButton()

# Client code
def build_ui(factory: GUIFactory):
    button = factory.create_button()
    button.render()
```

## Builder

**Purpose:** Separate the **construction of a complex object** from its representation, allowing **step-by-step creation**.

**Use Cases:**

- Building complex reports  
- Constructing AI models with multiple layers or components

**Python Example:**

```python
class Car:
    def __init__(self):
        self.parts = []

    def add_part(self, part):
        self.parts.append(part)

class CarBuilder:
    def __init__(self):
        self.car = Car()

    def add_engine(self):
        self.car.add_part("Engine")
        return self

    def add_wheels(self):
        self.car.add_part("Wheels")
        return self

    def build(self):
        return self.car

# Usage
builder = CarBuilder()
car = builder.add_engine().add_wheels().build()
print(car.parts)  # ['Engine', 'Wheels']
```

## Prototype

**Purpose:** Create new objects by **cloning an existing object**, avoiding expensive instantiation.

**Use Cases:**

- Duplicating AI model configurations  
- Copying large datasets or objects with default settings

**Python Example:**

```python
import copy

class Prototype:
    def __init__(self, data):
        self.data = data

# Original object
original = Prototype([1, 2, 3])

# Clone object
clone = copy.deepcopy(original)
clone.data.append(4)

print(original.data)  # [1, 2, 3]
print(clone.data)     # [1, 2, 3, 4]
```

## Practical Examples

- **Python:** Dynamic AI components creation using Factory/Builder  
- **C++:** Using Singleton for configuration management  

```cpp
// C++ Singleton
class Logger {
private:
    static Logger* instance;
    Logger() {}
public:
    static Logger* getInstance() {
        if (!instance) instance = new Logger();
        return instance;
    }
};

// Usage
Logger* log1 = Logger::getInstance();
Logger* log2 = Logger::getInstance();
```

- **JavaScript:** Builder pattern for constructing UI components

```javascript
class Car {
    constructor() {
        this.parts = [];
    }
    addPart(part) { this.parts.push(part); return this; }
}

const car = new Car().addPart('Engine').addPart('Wheels');
console.log(car.parts); // ['Engine', 'Wheels']
```
