## Introduction

**Architectural patterns** provide high-level structures for **organizing entire software systems**.  
They define how **components interact**, how data flows, and how responsibilities are distributed across modules.

**Key Points:**

- Focus on **system-level design**, not individual classes  
- Improve **scalability, maintainability, and flexibility**  
- Widely used in **web apps, AI pipelines, and enterprise software**

---

## MVC (Model-View-Controller)

**Purpose:** Separate an application into **three main components**:

- **Model:** Manages data and business logic  
- **View:** Handles the UI presentation  
- **Controller:** Processes input and coordinates between Model and View  

**Use Cases:** Web frameworks, GUI applications

**Python Example (Simplified):**

```python
# Model
class User:
    def __init__(self, name):
        self.name = name

# View
class UserView:
    def display(self, user):
        print(f"User: {user.name}")

# Controller
class UserController:
    def __init__(self, user, view):
        self.user = user
        self.view = view
    def update_user(self, name):
        self.user.name = name
    def show_user(self):
        self.view.display(self.user)

# Usage
user = User("Alice")
view = UserView()
controller = UserController(user, view)
controller.show_user()        # User: Alice
controller.update_user("Bob")
controller.show_user()        # User: Bob
```

## MVVM (Model-View-ViewModel)

**Purpose:** Facilitate **two-way data binding** between UI and data.  

- **Model:** Data and business logic  
- **View:** UI  
- **ViewModel:** Converts data for the View, handles UI logic  

**Use Cases:** Modern UI frameworks (React, Angular, WPF)

**Python Example:**

```python
class Model:
    def __init__(self, value):
        self.value = value

class ViewModel:
    def __init__(self, model):
        self.model = model
    def set_value(self, val):
        self.model.value = val
    def get_value(self):
        return self.model.value

class View:
    def __init__(self, viewmodel):
        self.viewmodel = viewmodel
    def render(self):
        print(f"Value: {self.viewmodel.get_value()}")

# Usage
model = Model(10)
vm = ViewModel(model)
view = View(vm)
view.render()     # Value: 10
vm.set_value(20)
view.render()     # Value: 20
```

## Microservices Patterns

**Purpose:** Decompose applications into **small, independent services** that communicate over APIs.

**Use Cases:**  

- Scalable AI/ML platforms  
- Distributed web applications  

**Key Concepts:**

- Each service has **own database**  
- Services communicate via **REST, gRPC, or message queues**  
- Enables **independent deployment**  

**Example:** Separate AI model training, prediction API, and data preprocessing into independent services.

---

## Event-Driven Architecture

**Purpose:** Components **react to events** asynchronously rather than calling each other directly.

**Use Cases:**  

- AI pipelines with streaming data  
- Real-time notification systems  

**Key Concepts:**

- **Event producers:** Generate events  
- **Event consumers:** React to events  
- **Event bus/message broker:** RabbitMQ, Kafka  

**Example:**  

- Model training triggers "model_ready" event  
- Deployment service listens and updates production models

---

## Layered / N-Tier Architecture

**Purpose:** Organize applications into **distinct layers**, each with a clear responsibility:

- **Presentation layer:** UI  
- **Application layer:** Business logic  
- **Data layer:** Database interactions  
- **Integration layer:** APIs, external services  

**Use Cases:** Enterprise apps, web apps, AI platforms

**Benefits:**

- Clear separation of concerns  
- Easier maintenance and testing  
- Allows layer-specific scaling

---

## How Patterns Influence AI/ML Systems

1. **Modularization:** Microservices or layered architecture help **isolate training, inference, and preprocessing**.  
2. **Scalability:** Event-driven systems handle **streaming AI data** efficiently.  
3. **Maintainability:** MVC/MVVM patterns separate **data, logic, and presentation**, making AI dashboards easier to manage.  
4. **Reusability:** Standardized patterns allow **reuse of models, APIs, and pipelines**.  
5. **Integration:** Architectural patterns simplify **integration with other tools** like monitoring, logging, and MLOps pipelines.
