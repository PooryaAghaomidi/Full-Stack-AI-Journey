## Error Handling

C++ provides mechanisms to handle errors and exceptions in a controlled way.

### Using Exceptions

```cpp
#include <iostream>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) throw std::runtime_error("Division by zero");
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 0) << "\n";
    } catch (const std::exception &e) {
        std::cout << "Error: " << e.what() << "\n";
    }
}
```

- **`try`**: block where exceptions might occur  
- **`throw`**: signals an exception  
- **`catch`**: handles the exception  
- **`std::exception`**: base class for standard exceptions

### Best Practices

- Prefer exceptions for unexpected errors  
- Use return codes for predictable errors (e.g., file not found)  
- Clean up resources using RAII (Resource Acquisition Is Initialization)

## File I/O

C++ provides **fstream** for file operations.

### Reading Files

```cpp
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream file("input.txt");
    std::string line;
    while (std::getline(file, line)) {
        std::cout << line << "\n";
    }
    file.close();
}
```

### Writing Files

```cpp
#include <fstream>
#include <iostream>

int main() {
    std::ofstream file("output.txt");
    file << "Hello, file!" << std::endl;
    file.close();
}
```

### Binary Files

```cpp
#include <fstream>

struct Data { int x; float y; };

int main() {
    Data d = {10, 3.14f};
    std::ofstream out("data.bin", std::ios::binary);
    out.write(reinterpret_cast<char*>(&d), sizeof(d));
    out.close();
}
```

**Tips**

- Always check if files open successfully: `if (!file.is_open())`  
- Use RAII (`std::ifstream`/`std::ofstream` in a local scope) to auto-close files  
- Handle exceptions or errors gracefully

## Package Management

C++ lacks a single standard package manager, but several tools exist:

### Popular C++ Package Managers

- **vcpkg**: Microsoft-supported, integrates with CMake  
- **Conan**: Cross-platform, widely used in professional projects  
- **Hunter**: CMake integration  
- **CPM.cmake**: Modern CMake dependency management

### Example with vcpkg

```bash
git clone https://github.com/microsoft/vcpkg.git
cd vcpkg
./bootstrap-vcpkg.sh
./vcpkg install fmt
```

Then integrate with CMake:

```cmake
find_package(fmt CONFIG REQUIRED)
target_link_libraries(myapp PRIVATE fmt::fmt)
```

**Best Practices**

- Use a single package manager per project  
- Lock dependency versions for reproducibility  
- Avoid heavy dependencies in headers

## Build Tools / Runtime Model

C++ projects rely on build systems and compilers to produce executables.

### Build Tools

- **Make / Makefiles**: simple, widely available  
- **CMake**: cross-platform, standard for modern C++  
- **MSBuild**: Visual Studio projects  
- **Ninja**: fast builds, often used with CMake

### Example CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyApp)
set(CMAKE_CXX_STANDARD 17)
add_executable(myapp main.cpp utils.cpp)
```

### Compilation & Linking

1. **Compile** `.cpp` → `.o` object files  
2. **Link** `.o` files → executable

```bash
g++ -c main.cpp -o main.o
g++ -c utils.cpp -o utils.o
g++ main.o utils.o -o myapp
```

### Runtime Model

- Executable runs directly on OS  
- Stack stores function frames; heap stores dynamic objects  
- Global/static variables initialized before main  
- RAII ensures resources are automatically freed

## Concurrency / Async

C++ has built-in support for threads and asynchronous tasks (`<thread>` and `<future>`).

### Threads

```cpp
#include <thread>
#include <iostream>

void worker(int id) {
    std::cout << "Worker " << id << " started\n";
}

int main() {
    std::thread t1(worker, 1);
    std::thread t2(worker, 2);
    t1.join();
    t2.join();
}
```

### Mutex & Synchronization

```cpp
#include <mutex>
#include <thread>
#include <iostream>

std::mutex mtx;
int counter = 0;

void increment() {
    for (int i = 0; i < 1000; i++) {
        std::lock_guard<std::mutex> lock(mtx);
        counter++;
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    std::cout << counter << "\n"; // 2000
}
```

### Async / Futures

```cpp
#include <future>
#include <iostream>

int compute() { return 42; }

int main() {
    std::future<int> result = std::async(std::launch::async, compute);
    std::cout << result.get() << "\n";
}
```

**Best Practices**

- Avoid data races and deadlocks  
- Use `std::thread`, `std::mutex`, `std::lock_guard` carefully  
- Prefer high-level abstractions (`std::async`, thread pools) when possible

## Debugging Basics

C++ debugging requires tools and techniques:

### Tools

- **GDB**: GNU debugger  
- **LLDB**: LLVM debugger  
- IDE debuggers: Visual Studio, CLion  
- Sanitizers: AddressSanitizer, ThreadSanitizer, UndefinedBehaviorSanitizer

### Common Debugging Techniques

- Set breakpoints to inspect variable values  
- Step through code line by line  
- Print debug info for quick checks (`std::cout`)  
- Use assertions: `assert(condition)`  

### Example GDB Session

```bash
g++ -g main.cpp -o main
gdb ./main
(gdb) break main
(gdb) run
(gdb) print variable
(gdb) next
(gdb) continue
```

## Common Gotchas / Tips

- **Dangling pointers**: avoid using deleted memory  
- **Uninitialized variables**: always initialize  
- **Memory leaks**: use RAII or smart pointers (`std::unique_ptr`, `std::shared_ptr`)  
- **Copy vs reference semantics**: know when objects are copied vs referenced  
- **Integer division**: dividing two integers truncates toward zero  
- **Floating-point precision**: beware of rounding errors  
- **Header guards**: prevent multiple inclusion of headers  
- **Namespace collisions**: prefer `namespace` or `using` with caution  
- **Compile-time errors**: read carefully, often indicate type or syntax issues
